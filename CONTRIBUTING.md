# Contributing to dav1d-rs

Thanks for your interest in contributing!

## Repository layout

- `src/lib.rs` — the safe `dav1d` wrapper crate.
- `dav1d-sys/` — FFI bindings and `build.rs` (library discovery via `system-deps`, with optional internal dav1d build).
- `tools/` — `dav1d-tools`, a work-alike of the `dav1d` command line tool built on the safe wrapper (not published).
- `.github/workflows/dav1d.yml` — CI (Linux, Windows and an MSRV check).

## Prerequisites

- Rust toolchain with **MSRV 1.85** (edition 2021) for the published crates. CI has a dedicated job checking it.
- `dav1d-tools` needs **1.88** because of `winnow-args`; it is excluded from the MSRV job.
- A working C toolchain.
- `meson` and `ninja` when building dav1d from source (CI builds dav1d 1.5.4 internally).
- `pkg-config`/`pkgconf` so `system-deps` can locate `libdav1d` (or set `SYSTEM_DEPS_DAV1D_BUILD_INTERNAL=always` to build it from source).

## Development workflow

1. Fork and create a branch off `master`.
2. Make focused changes with clear commit messages (past history uses short imperative subjects like `dav1d-sys: Fix ...` / `Prepare for release`).
3. Format and lint:
   ```sh
   cargo fmt --all
   cargo clippy --workspace --all-features --all-targets
   ```
4. Run the test suite:
   ```sh
   cargo test --workspace --all-features
   ```
   To force a known-good internal dav1d build (matches CI): 
   ```sh
   SYSTEM_DEPS_DAV1D_BUILD_INTERNAL=always cargo test --workspace --all-features
   ```
5. Open a pull request against `rust-av/dav1d-rs`.

CI must pass on Linux and Windows. Please avoid unrelated refactors in the same PR.

## Working on the FFI (`dav1d-sys`)

`dav1d-sys/src/lib.rs` is a **hand-written, platform-independent** binding to dav1d's public C API (it is not generated by bindgen). Changes here are ABI-sensitive:

- Keep struct layouts, field order/types, and `repr` attributes identical to the matching dav1d headers.
- Update or add the size assertions in `dav1d-sys/src/lib.rs` (`#[cfg(test)] mod tests`) when touching layout-critical types.
- Bump `dav1d-sys` with the appropriate semver impact (layout/API breaks require a breaking version bump).

The safe wrapper depends on `dav1d-sys` via a path dependency and re-exports `dav1d_sys::Dav1dPicture` for interop; keep that relationship coherent when bumping versions.

## Reporting issues

- Bugs and feature requests: https://github.com/rust-av/dav1d-rs/issues
- Please include your `dav1d` library version, platform, Rust version, and a minimal reproduction or sample bitstream when relevant.

## Release process (maintainers)

1. Land the changes on `master` with CI green.
2. Bump versions in `Cargo.toml`, `dav1d-sys/Cargo.toml`, and `tools/Cargo.toml` (and the `dav1d-sys` dependency in the root crate) in a `Prepare for release` commit.
3. Tag the release (e.g. `v0.12.0`).
4. Publish `dav1d-sys` first, then `dav1d`:
   ```sh
   cargo publish -p dav1d-sys
   cargo publish -p dav1d
   ```
